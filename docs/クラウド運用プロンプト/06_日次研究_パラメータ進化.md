# 06｜日次研究（パラメータ探索と自動進化）クラウド運用プロンプト

作成: 2026-08-16 ／ 対象: 全4システムのパラメータ研究と、頑健性ゲートを通った時だけの自動進化

## 4本の研究スクリプトと担当

| スクリプト | 対象 | 所要 | 現行の実行タイミング |
|---|---|---|---|
| `research.py` | 第1 長期トレンド／第2 短期スイング | 約3分 | 平日8時台（朝の最終確定の後） |
| `research_intraday.py` | 第3 デイトレ複合時間軸（2H） | 約10〜25分 | 平日15時台 |
| `research_15m.py` | 第4 デイトレ15分 | 約15分 | 平日15時台 |
| `research_fundamental.py` | ファンダ・予測（進化はしない） | 約1分 | 3時間ごと → `04_ファンダ予測研究.md` |

## クラウド適合性
いずれも長期の価格履歴が要るため**クラウド既定環境では動かない**（EGRESS_BLOCKED）。
モードB（ローカル）かモードA（GitHub Actions）で走らせる。
Actionsなら実行時間の制約も緩く、むしろ研究向き（`08_GitHubActions移行手順.md`）。

## ★日次研究は「パラメータ探索」だけでは不足（ユーザー必須要件）
2026-08-05／08-11の指示により、毎日次の4観点をすべて点検する:
1. **パラメータ探索**（下記の自動進化）
2. **シグナルの信用性** — 前日の指示と実際の値動きの整合、データ欠損・遅延、
   指標イベント判定の妥当性、モデルポジと実口座の乖離
3. **システム運営** — 完成率（実行の抜け漏れ）、リトライ・失敗の発生状況、
   Webボード公開の遅延・失敗
4. **運用ボードの表示研究** — ボードHTMLを実際に読み、整合性・鮮度を点検し、
   見づらい／誤解を招く箇所を毎日1点以上見つけて改修または改善案として記す

## 1) パラメータ探索

対象システムに応じて実行する:

```
python3 src/research.py             # 日足2システム（約3分）
python3 src/research_intraday.py    # デイトレ2H（約10〜25分）
python3 src/research_15m.py         # デイトレ15分（約15分）
```

- 頑健性ゲート（前後半PF基準・取引数下限・最大DD・現行スコア比1.05倍以上）を
  満たした場合のみ `config.json` を書き換えて自動進化する（翌回判定から適用）。
- 標準出力の「進化したシステム:」行を確認する。
- **進化を採用した場合は、必ずクラウド代行プロンプトの定数も更新する**:
  - `02_デイトレ複合時間軸2H.md` の `TF_H / ENTRY_N / EXIT_N / ATR_K / TP_K / FILTER_4H_N / CONFIRM_MACD`
  - `03_デイトレ15分.md` の `TF_MIN / ENTRY_N / EXIT_N / ATR_K / TP_K / RISK`
  - `01_日足2システム.md` の `SYSTEMS`
  - 各ファイル冒頭の「現行パラメータ」行
  - Driveの「マイドライブ/FXドル円自動売買」へ再コピー
  （クラウド版とMac版の判定を常に一致させるため。ここを忘れると**判定が食い違う**）

## 2) 完成率の点検（目標100%）

```
python3 src/run_intraday.py --check      # デイトレ2Hの毎時実行
python3 src/run_intraday15.py --check    # デイトレ15分の実行
```

100%未満なら欠落時間帯の原因（Macスリープ・launchd停止・データ取得失敗）を
`run_log_intraday.csv` / `launchd_intraday.log` から調べる。launchdが止まっていれば:

```
launchctl load ~/Library/LaunchAgents/com.ochiai.fx-intraday.plist
launchctl load ~/Library/LaunchAgents/com.ochiai.fx-intraday15.plist
```

## 3) 整合点検

- `state_intraday.json` / `state_intraday15.json` のモデルポジ（position/stop/tp）と
  `results/intraday_latest.txt` / `intraday15_latest.txt` の指示が一致しているか。
- 逆指値・利確指値が設計どおり（ATR×3.0 / ATR×6.0）か。
- **クラウド代行版との突合**（★2026-08-16に追加した新点検）:
  `01`〜`03` のクラウドスクリプトを実行し、Mac版の state と一致するか確かめる。
  食い違ったら「どちらが正しいか」ではなく「なぜ食い違うか」を必ず突き止める。
  既知の食い違い要因は次の2つ:
  - 日足系: Mac版は朝8時の**未確定バーの暫定終値**で建玉するため、後日Yahooが終値を
    改訂すると履歴リプレイでは再現できない（→シードを使えば一致する）
  - Macが処理していない新しいバーまでクラウド版が進んでいる（休場明けに自然解消）

## 4) 運用ボードの表示研究

`python3 src/dashboard_web.py` で再生成し、`results/dashboard_web.html` を実際に読む:
- **整合性**: カードのアクション/ポジション表示・運用成績KPI・資産推移が、当日の指示書本文
  および `state.json` / `trades.csv` と矛盾していないか。
- **鮮度**: レート・更新時刻・完成率チップが最新か。
- **改善**: 見づらい／誤解を招く／情報が足りない箇所を**毎日1点以上**探し、
  軽微なら即改修、大掛かりなら改善案として記す。改修したら報告に明記する。

## 5) 毎日必ず1通、研究サマリをプッシュ通知する（変化がない日も送る）

形式:
「【デイトレ日次研究】進化なし・現行2H 12/6が最良（スコア1.34）／完成率17/17=100%／
 現況: 売4,000通貨・逆指値158.88円・利確155.95円維持／15分完成率◯/◯」

- 進化した場合: 「【デイトレ進化】◯H ドンチャン◯/◯・ATR×◯へ更新。次回判定から適用
  （頑健スコア◯→◯）」
- 完成率100%未満: 「⚠完成率◯/◯・欠落◯時台=原因」を必ず含め、復旧済みかも書く。
- 研究が失敗した場合: 「⚠研究スキップ=理由」を付記する（探索の失敗は翌日持ち越しでよいが、
  完成率点検と通知は必ず行う）。
- 末尾にファンダ1行を足す（`results/fundamental_latest.json` から読む）。例:
  「／レジーム: ドル全面主導(DXY+0.60)・焦点=米CPI8/12・予測45%下落(検証52.2%＝
   エッジなしのため発注不使用)」
- `fundamental_latest.json` の「更新」が6時間以上前なら
  「⚠ファンダ研究が◯時から未更新」を付記する（本プロンプトからは復旧させず報告に留める）。

## 厳守事項

- **`config.json` / `state*.json` / `results` 配下は各スクリプトが管理する。手動編集しない。**
- 発注は絶対に自動化しない。JFX（MATRIX TRADER）はEA・自動売買が規約で禁止。
  証券会社サイト・取引アプリへのログイン・操作は一切しない。
- 進化の採否は頑健性ゲートが決める。**ゲートを緩めて無理に進化させない。**
- ペア追加・乗換えは日次研究の権限外（→ `05_週次ペア研究.md`）。ユーザー判断を仰ぐ。
