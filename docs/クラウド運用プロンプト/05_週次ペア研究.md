# 05｜週次 通貨ペア横断研究 クラウド運用プロンプト

作成: 2026-08-16 ／ 対象: 毎週土曜9時（市場休場中）
現行タスク: `fx-pair-research-weekly`（Mac側スケジュールタスク）

## 何をする研究か
主要11通貨ペアの15年日足を取得し、現行2システム（`config.json` のパラメータに自動追随）で
頑健性検証する。ドル円以外の上位2ペアには専用パラメータ最適化も行い、
**「現行スキームにとって最適な通貨ペアがドル円のままか」**を毎週確かめる。

## クラウド適合性
`pair_scan.py` は15年×11ペアのYahoo日足を必要とするため、**クラウド既定環境では動かない**
（EGRESS_BLOCKED）。実行は次のいずれか:
- モードB: Mac／手元PCのClaudeセッション（現行どおり）
- モードA: GitHub Actions（`cron: '0 0 * * 6'` UTC ＝ 土曜9時JST）→ `08_GitHubActions移行手順.md`

WebSearchによる代替は**不可**（15年ぶんの日足を検索では取れない）。
本研究だけはデータ取得経路を確保してから移すこと。

---

━━━━━━━━━━ 運用プロンプト（ここから下を貼り付け） ━━━━━━━━━━

FXドル円半自動売買スキームの週次「通貨ペア横断研究」を代行してください。
途中でユーザーへの確認は不要です（完全自動）。

## 1) ペアスキャンを実行する（約2〜4分）

```
cd "$HOME/FXドル円自動売買スキーム" && python3 src/pair_scan.py --tuned 2
```

- 結果は `results/pair_scan.csv`（最新）と `pair_scan_log.csv`（履歴）に自動保存され、
  Driveダッシュボードの「ペア研究」シートにも自動反映される。
- Yahoo Financeが一時的に500エラーを返すことがある（スクリプト内で自動リトライ済み）。
  それでも一部ペアが失敗した場合は5分待って再実行する。**最大2回**まで。
- `EGRESS_BLOCKED` で失敗した場合はクラウド既定環境で動かない証拠。
  実行環境を切り替える旨を報告して終える（無理に代替しない）。

## 2) 標準出力の「判定:」行を読み取る

3パターンある。プッシュ通知（PushNotification・status: proactive）で送る:

- **「ドル円優位継続」** → 簡潔に:
  「【週次ペア研究】ドル円優位継続（長期score◯◯、次点◯◯ ◯◯）。全11ペア検証済」
- **「接近: ...」** → 注意を付ける:
  「【週次ペア研究・注目】◯◯がドル円の9割圏内に接近（score◯◯）。来週も監視」
- **「要注目: ...」** → 目立つ通知:
  「【週次ペア研究・要検討】◯◯がドル円に並ぶ/超えるスコア。乗換え/追加の検討候補。
   詳細はダッシュボード『ペア研究』シート」
  ＋ **JFX公式スプレッド一覧（https://jfx.co.jp/spread_list/index.html）での実スプレッド確認が
  必要な旨を必ず添える**（スクリプト内PAIRSのスプレッドは一部が想定値のため）。

## 3) 失敗時

最終的に失敗した場合は【エラー】として簡潔にプッシュ通知する
（週次研究のため翌週リカバリでも支障ない旨を添える）。

## 厳守事項

- **このタスクは調査・研究のみ。** 発注・口座操作・`config.json` の書換えは一切行わない。
  パラメータの自動進化は日次研究（`06_日次研究_パラメータ進化.md`）の役割であり、
  **ペア追加や乗換えは必ずユーザーの判断を仰ぐ事項**。勝手に新ペアを追加しない。
- 祝日・休場は関係なく実行してよい（過去データの研究のため）。
- 発注は絶対に自動化しない。証券会社サイト・取引アプリへのログイン・操作は一切しない。
