# 発注カード規約（全スキル共通）

2026-08-18 ユーザー厳命。**発注カードには必ず見やすく「利確幅・損切り幅 PIPS」を記載する。**

## 1. 必ず出す欄

```
  ──── 幅（pips）────
  利確幅      : 約136 pips／+27,120円（想定約定159.456 → 利確158.100）
  損切り幅    : 約78 pips／-15,680円（想定約定159.456 → 逆指値160.240）
  RR          : 1.73（利確幅 ÷ 損切り幅）
```

- 並びは **利確幅 → 損切り幅**（ユーザー文言どおり）
- 該当しない場合も空欄にせず理由を書く
  - 日足2システム: `利確幅 : —（利確目標を置かない設計）`
  - 成行決済: `—（決済のため設定なし）`
  - 約定確認: `—（約定確認のみ。新たな注文は出さない）`

## 2. 保有玉には「現値から」を併記する

```
  現値から    : 148.140円 → 逆指値まで 24 pips／利確まで 86 pips
```

建値基準の幅は「その注文に当たったら確定する損益」、現値基準の距離は
「いま値段があと何pipsでその注文に当たるか」。**転記直後に実務で効くのは後者**。
両方を出す。

## 3. トレール後の逆指値は「損切り」ではないことがある

買玉の逆指値が建値より上（売玉なら下）へトレールされている場合、その注文に
当たっても損失ではなく**利益の確定**になる。カードは次のように書く。

```
  損切り幅    : 約90 pips／+27,000円（建値147.000 → 逆指値147.900／到達しても +90 pips の利益確保）
```

## 4. 計算はCowork側で絶対に行わない

幅の計算元は Actions 側 `src/risk.py` の `order_widths()` **ただ一つ**。
同じ数字を2箇所で計算すると、片方だけ直し残る事故が必ず起きる（過去に発生済み）。

- 指示書テキストの「幅（pips）」欄を**そのまま転記**する
- 機械可読JSONを使うなら `損切り幅pips_数値` `利確幅pips_数値`
  `現値から逆指値pips_数値` `現値から利確pips_数値` を読む
- 欄が無い（旧版エンジンの回）ときは、**補完せずに「記載なし」と報告する**

## 5. 用語の禁止事項

**ドンチャンの決済ラインを「利確」と呼ばない。**トレンド転換で降りる線であり、
含み損のまま到達すれば損切りとして働く。RRの分子にも入れない。
日足2システムの利確欄は「—（利確目標を置かない設計）」が正しい表記。
