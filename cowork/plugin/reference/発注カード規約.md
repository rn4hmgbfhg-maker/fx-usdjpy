# 発注カード規約（全スキル共通）

2026-08-18 ユーザー厳命。**発注カードには必ず見やすく「利確幅・損切り幅 PIPS」を記載する。**

## 1. 必ず出す欄

```
  ──── 幅（pips）────
  利確幅      : 約136 pips／+27,120円（想定約定159.456 → 利確158.100）
  損切り幅    : 約78 pips／-15,680円（想定約定159.456 → 逆指値160.240）
  RR          : 1.73（利確幅 ÷ 損切り幅）
```

- 並びは **利確幅 → 損切り幅**（ユーザー文言どおり）
- 該当しない場合も空欄にせず理由を書く
  - 日足2システム: `利確幅 : —（利確目標を置かない設計）`
  - 成行決済: `—（決済のため設定なし）`
  - 約定確認: `—（約定確認のみ。新たな注文は出さない）`

## 2. 保有玉には「現値から」を併記する

```
  現値から    : 148.140円 → 逆指値まで 24 pips／利確まで 86 pips
```

建値基準の幅は「その注文に当たったら確定する損益」、現値基準の距離は
「いま値段があと何pipsでその注文に当たるか」。**転記直後に実務で効くのは後者**。
両方を出す。

## 3. トレール後の逆指値は「損切り」ではないことがある

買玉の逆指値が建値より上（売玉なら下）へトレールされている場合、その注文に
当たっても損失ではなく**利益の確定**になる。カードは次のように書く。

```
  損切り幅    : 約90 pips／+27,000円（建値147.000 → 逆指値147.900／到達しても +90 pips の利益確保）
```

## 4. 計算はCowork側で絶対に行わない

幅の計算元は Actions 側 `src/risk.py` の `order_widths()` **ただ一つ**。
同じ数字を2箇所で計算すると、片方だけ直し残る事故が必ず起きる（過去に発生済み）。

- 指示書テキストの「幅（pips）」欄を**そのまま転記**する
- 機械可読JSONを使うなら `損切り幅pips_数値` `利確幅pips_数値`
  `現値から逆指値pips_数値` `現値から利確pips_数値` を読む
- 欄が無い（旧版エンジンの回）ときは、**補完せずに「記載なし」と報告する**

## 5. 用語の禁止事項

**ドンチャンの決済ラインを「利確」と呼ばない。**トレンド転換で降りる線であり、
含み損のまま到達すれば損切りとして働く。RRの分子にも入れない。
日足2システムの利確欄は「—（利確目標を置かない設計）」が正しい表記。

## 6. 反映先（1か所直して終わりにしない）

指示書本文／発注カード／即時メール／スマホプッシュ要旨／Webボード／
クラウド運用プロンプト／スケジュールタスクのSKILL.md／本パッケージのスキル。
いずれかを直したら全部を突合する。


## 7. 新規建ては IF-DONE／IF-OCO で「1回送信」（2026-09-21 実機検証で確定）

成行を単独で出してから決済逆指値を後付けする手順は廃止。約定〜逆指値セットの間に
「逆指値のない時間」ができるため。MATRIX TRADER（Mac版）の新規注文は IF-DONE／IF-OCO の
IF(新規)側で**成行**を選べ、決済側はレート指定できる（実機で入力・読み戻し確認済み）。

| 系統 | 注文方法の表記 | タブ |
|---|---|---|
| 日足2システム（利確なし） | `IF-DONE（新規=成行／決済=逆指値）` | IF-DONE |
| デイトレ2H・15分（利確あり） | `IF-OCO（新規=成行／OCO1利確=指値／OCO2損切=逆指値）` | IF-OCO |
| デイトレで利確なしの回 | `IF-DONE（…）` | IF-DONE |

- 逆指値変更・決済はこれまでどおり1注文ずつ（カード1枚＝送信1回。複数カードの一括送信は不可）
- 「決済pip差設定」（ペア単位の固定値）は使わない。入力は必ずカードのレート値
- 画面の「予想損益 ○○ pips」は 0.001円単位（2,121 と出れば約212pips）で、基準も現値。
  **照合は損益欄ではなくレート値そのもので行う**

### 転記入力の実務ルール（同日検証）

- 「確認画面を表示」を常時オン（送信が「注文確認画面へ」の2段階になる＝発注手前の停止点）
- Lot・レートはキーボード入力禁止（Lot欄に「2」を打つと 15→17 になる事象を確認）。
  欄右の格子アイコンのテンキー（プリセット＋±1000/±100/±10/±1）で加算式に入れる
- 座標は「撮影→等倍切り出し→算出」。縮小表示画像から座標を取ると約30%ずれる
- 入力のたびに読み戻し（スクリーンショット）でカード値と突合。送信は必ず本人
- 既定値が Lot 15・指値のため、毎回 Lot と執行条件を上書きして読み戻すこと
