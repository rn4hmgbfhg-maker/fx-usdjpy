# fx-watch — 判定基盤の見張り番

## なぜ必要か

Macのlaunchdから GitHub Actions へ移行したことで、判定が止まったときに
気づく手段が無くなった。Actionsが失敗しても静かに止まるだけで、
**古い逆指値のまま相場が動く**のが最大のリスク。鮮度で検知する。

## 手順

### 1. 鮮度を確認する

```bash
python3 scripts/fx_fetch.py --status
```

`警告` 配列を見る。しきい値は既定60分（`FX_STALE_MIN` で変更可）。
Actionsは15分間隔なので、60分の空白は明確な異常。

判定ロジック（`fx_fetch.py` が実施済み。ここでは再実装しない）:

- 各系統の `更新` / `updated` を現在JSTと比較
- 市場休場（土13:00 JST 〜 月06:00 JST）なら `鮮度: 休場中` として警告しない
- それ以外で60分超なら `鮮度: 古い` ＋ 警告文

### 2. 正常なとき

「正常（最終更新 06:05・32分前）」と1行返すだけ。
**ルーティン実行時は通知を鳴らさない。**

### 3. 鮮度切れを検知したとき

PushNotification（status: proactive）を1本送る。

```
【FX異常】判定が94分間更新されていません。GitHub Actions の fx-signals を確認してください。
建玉は 長期トレンド売2,000／デイトレ15分買7,000 が残っています。
```

続けて、ユーザーが取るべき行動を提示する。

1. GitHubの Actions タブで `fx-signals` の最新実行を確認（失敗していれば赤）
2. 手動実行（workflow_dispatch）で復旧できることが多い
3. 復旧しない間は、MATRIX TRADERに置いてある逆指値がそのまま生きているので
   **建玉が無防備になるわけではない**。ただしトレイル更新は止まる

### 4. 取得そのものが失敗したとき

`fx_fetch.py` が `【エラー】取得失敗` を返した場合は、Cowork側のegress問題。

- 宛先が `raw.githubusercontent.com` 以外になっていないか確認する
- 金融API（Yahoo等）はクラウドから遮断されているため、代替取得は成立しない
- この場合も通知を送り、「クラウドからデータ経路に到達できない」と明示する

## やってはいけないこと

- 正常時に通知を鳴らす（毎時鳴ると見なくなる）
- 休場中の更新停止を異常として通知する
- 鮮度切れを検知したのに、古い数字を「現在の状況」として提示する
- 自分でActionsを再実行しようとする（権限が無い。ユーザーに依頼する）
