# fx-research — 研究結果の要約

## 手順

### 1. 最新の研究ログを取る

```bash
python3 scripts/fx_fetch.py --research
```

返るキー:

| キー | 中身 |
|---|---|
| `日次研究(パラメータ進化)` | results/research_log.csv の最新行 |
| `週次ペア研究` | results/pair_scan_log.csv の最新行 |
| `ファンダ予測` | results/forecast_log.csv の最新行 |
| `実現損益(日次ログ)` | results/daily_log.csv の最新行 |

各値は `{見出し: "...", 最新: ["...", "..."]}`。見出しと値を突き合わせて読む。

### 2. 週次ペア研究の伝え方

判定は3パターン。

| 判定 | 伝え方 |
|---|---|
| ドル円優位継続 | 「ドル円優位継続（長期score◯◯、次点◯◯ ◯◯）。全11ペア検証済」 |
| 接近 | 「◯◯がドル円の9割圏内に接近（score◯◯）。来週も監視」 |
| 要注目 | 「◯◯がドル円に並ぶ/超えるスコア。乗換え/追加の検討候補」＋**JFX公式スプレッド一覧での実スプレッド確認が必要**な旨を添える（スキャンの一部スプレッドは想定値のため） |

**ペアの追加・乗り換えを自分で決めない。**必ず候補として提示し、判断を仰ぐ。

### 3. 日次研究（パラメータ進化）の伝え方

- 現行パラメータと候補パラメータのスコア・PF・勝率・トレード数を並べる
- **トレード数が少ない候補は過剰適合を疑う**旨を添える
- 採用提案があっても config を書き換えるのはActions側の日次研究タスクの役割であり、
  Coworkからは書き換えない。「採用しますか」と聞く

既知の方針（研究済み・繰り返し提案しない）:

- 勝率はエントリー期間で決まり、利確を足しても上がらない。
  短期スイングは構造的に勝率50%超が不可能で、現状維持でよい。
- 長期は 70/10・ATR3.0 で勝率53.6%・PF2.97 という上位案が既に見つかっている
  （現行 40/10・ATR3.5 は勝率43.9%・PF2.58）。採用可否はユーザー判断待ち。

### 4. 成績（実現損益）の伝え方

`実現損益(日次ログ)` の最新行を読む。ただし4システム合算の資産カーブは
Actions側の `perf.py` が正であり、daily_log のモデル資産列は日足2システム分しか
含まない。**「日足2システムの記録」と明示**して伝えるか、合算が必要なら
Actions側の出力を待つ。ここで合算を自作しない。

### 5. 通知（ルーティンから呼ばれた場合）

- `fx-research-weekly`（土9時）: 週次ペア研究の判定を1本
- `fx-research-daily`（平日15:30）: 採用提案がある時だけ1本。無ければ沈黙

## やってはいけないこと

- パラメータやペアの採用を自分で決める・configを書き換える
- 少ないトレード数の好成績を「改善」として無条件に薦める
- 既に却下済みの方針（短期スイングへの利確追加など）を再提案する
- 合算成績を自分で足し算して出す
