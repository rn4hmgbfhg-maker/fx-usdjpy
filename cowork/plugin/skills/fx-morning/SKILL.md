# fx-morning — 日足2システムの朝の指示書

## 前提

- 判定は GitHub Actions が JST 6/7/8時台に3段階（速報1→速報2→最終確定）で実行済み。
- Cowork は結果を読むだけ。**売買判定もpips計算も一切しない。**
- 発注は JFX MATRIX TRADER で**本人が手動**で行う（EA禁止のため代行しない）。

## 手順

### 1. 指示書を取得する

```bash
python3 scripts/fx_fetch.py --card
```

ステージを指定する場合は `--stage 確定` / `--stage 速報2` / `--stage 速報1`。
出力は「指示書の本文」＋末尾1行のメタJSON（`段階` `発注可` `pips欄` `エンジン版`）。

### 2. 段階を確認して、発注してよいかを最初に伝える

| 段階 | 伝えること |
|---|---|
| 確定 | 「最終確定です。このカードで発注できます」 |
| 速報2 / 速報1 | 「**速報段階です。まだ発注しないでください**。最終確定はJST8時台に出ます」 |
| 未生成 | 「本日の指示書はまだありません（JST6時台以降に生成）」。前日分を代わりに出さない |

### 3. 発注カードをそのまま提示する

指示書本文の `◆ 発注カード` 以降をそのまま見せる。整形し直してもよいが、
**数値は1つも変えない・足さない**。カードには次が必ず含まれている。

```
  ──── 幅（pips）────
  利確幅      : —（利確目標を置かない設計）
  損切り幅    : 約411 pips／-8,222円（建値157.272 → 逆指値161.383／到達なら -411 pips の損失）
  現値から    : 159.492円 → 逆指値まで 189 pips
```

- 並びは**利確幅 → 損切り幅**。
- 日足2システムは利確指値を置かない設計なので、利確幅は「—」で正しい。
  これを「利確◯pips」と書き換えてはいけない（ドンチャンの決済ラインは利確ではない）。

### 4. 「幅（pips）」欄が無かったら

メタJSONの `pips欄` が `false` の場合、リポジトリのエンジンがpips対応前の旧版。
このときは**pipsを自分で計算して補わない**。次のように報告する。

> このカードはpips対応前のエンジンが生成したもので、利確幅・損切り幅の欄がありません。
> 移行手順M1（pips対応版srcのpush）が未実施です。逆指値のレートのみ確定値として使えます。

### 5. 発注作業が無い日

カードが「本日の発注作業: なし」なら、その旨と現在の建玉・逆指値までの距離を1〜2行で伝える
（距離は `python3 scripts/fx_fetch.py --status` ではなく、指示書本文の【継続】行に
書かれている「現値◯円 → 逆指値まで N pips」を転記する）。

### 6. 定時実行のとき（ルーティン fx-morning-final から呼ばれた場合）

PushNotification（status: proactive）を1本送る。文面は200字以内で、

- 発注ありの最終確定: `【FX確定】長期トレンド ストップ変更 161.383円（損切り411pips・現値から189pips）／短期スイング ストップ変更 160.898円`
- 発注なし: `【FX確定】本日の発注作業なし。長期トレンド 逆指値まで189pips・短期スイング 141pips`
- 速報止まり: `【FX】8時台の最終確定がまだ出ていません。Actionsの fx-signals を確認してください`

## やってはいけないこと

- pips幅・ロット・逆指値レートを自分で計算する（Actions側 risk.order_widths() が唯一の計算元）
- 速報段階のカードで「発注してください」と促す
- 取得に失敗したときに前日や記憶の数字で埋める（「取得できませんでした」と言う）
- 本人に代わって発注する（規約違反。カードの提示までが役割）
